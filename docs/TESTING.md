# 検証記録

## 対象

提供されたWord版「ゲーム企画書」「Codex実装指示書」に基づく **5×5盤・全5戦・React + TypeScript + Vite + Vitest** の実装を対象とする。

仕様確認前の別ルール実装に対する旧38件のテスト結果とスクリーンショットは、最終仕様の検証結果として扱わない。以下はWord仕様への更新後に実行した結果。

## 実行コマンド

Node.js 24以上の環境で、リポジトリ直下から実行する。

```sh
npm ci
npm test
npm run build
npm run preview
```

`npm test` は Vitest の単体テスト。`npm run build` は TypeScript 型検査とViteの本番ビルド。`npm run preview` は生成した `dist/` をローカル配信する。

## 検証途中の失敗と対処

- このWindowsサンドボックス内では、Vite/Vitestの設定読込でesbuildが `Access is denied` となった。通常権限で再実行し、最終46件とビルドが成功。
- 既存の `dist/` を更新するビルドが、変換後に終了コード1で止まる事象があった。`--emptyOutDir false` で生成できることを確認後、削除先の絶対パスが作業フォルダ内の `dist/` であることを確認し、この生成物だけを削除。標準の `npm run build` を改めて実行して成功した。GitHub Actionsはクリーンなチェックアウトからビルドする構成。
- Word文書を受け取る前の仮実装と古いテストへの参照は正式仕様へ置き換え、改めて全件を検証した。

## iPhoneの表示崩れへの対応

2026-10-17、iPhoneの写真で、盤面の外枠だけが正方形になり、マスと駒が上端へつぶれる表示と、ヘッダーが上部へ隠れる表示が報告された。初回のChromiumによる画面幅・要素数の確認では、Safari系の表示や実際のマスの高さ、画面の安全領域を検証できていなかった。

- 盤面を高さの確定する正方形ラッパー内へ配置し、5行5列とマスの高さを明示。駒・利き・配置候補の位置もマス中央へ固定し、Safariのボタン既定描画を解除。
- `viewport-fit=cover` に対応し、ヘッダーの高さと上余白、縦横画面の左右余白へ `safe-area-inset-*` を反映。
- E2EをChromiumとWebKitの両方へ拡張。13回の画面幅・向き変更で25マスの実寸、正方形、5行5列、駒本体・文字のセル内包含、ヘッダー文字・アイコンの実寸を検査。
- 上47px、左47px、右47px、左右47pxの4つの安全領域をCSS変数で模擬し、タイトルとアイコンが隠れないことを検査。旧公開版は上47pxの検査で失敗し、修正版は成功。
- WindowsのWebKit 27.2では、旧版の盤面がつぶれる実機と同じ症状は再現しなかった。写真とCSSの高さ依存をもとに、その依存を除去した。iPhone実機そのものの検証と、WebKitの自動検証は区別する。
- 修正後、46件の単体テスト・型検査・本番ビルドに成功。ChromiumとWebKitの両方で配置、保存復元、全5戦のクリア、敗北後の再挑戦、本番サブパス配信まで成功。戦闘の結果・ルールは変更していない。
- GitHub Actionsでも両ブラウザの表示と通しプレイが成功した場合だけPagesへ公開するよう変更。

ブラウザの画面証跡は `artifacts/formal-*-chromium.png` と `artifacts/formal-*-webkit.png`（Git管理対象外）。
