# 検証記録

## 対象

提供されたWord版「ゲーム企画書」「Codex実装指示書」に基づく **5×5盤・全5戦・React + TypeScript + Vite + Vitest** の実装を対象とする。

仕様確認前の別ルール実装に対する旧38件のテスト結果とスクリーンショットは、最終仕様の検証結果として扱わない。以下はWord仕様への更新後に実行した結果。

## 実行コマンド

Node.js 24以上の環境で、リポジトリ直下から実行する。

```sh
npm ci
npm test
npm run build
npm run preview
```

`npm test` は Vitest の単体テスト。`npm run build` は TypeScript 型検査とViteの本番ビルド。`npm run preview` は生成した `dist/` をローカル配信する。

## ブラウザ確認項目

- 新規ラン→初期配置→戦闘開始→勝利→3択駒報酬→次戦準備→第5戦→最終報酬→クリア。
- 王捕獲による敗北、80半手・双方連続パスの敗北、再挑戦。
- 再生・一時停止・1手送り・速度変更、AIの判断理由と能力ログ。
- 準備画面の敵配置・危険マス、位置交換・控え、王を外せないこと。
- 陣営を文字と向きでも区別できること、キーボードによる基本操作。
- スマートフォンを想定した狭い画面で、盤面・報酬・操作ボタンが利用でき、横にはみ出さないこと。
- 本番ビルドをリポジトリ名のサブパスで配信し、相対アセットが読めること。
- 追加機能の保存・復元と、戦闘中の再読込が一時停止になること。保存不可でもプレイを継続できること。

## 最終仕様での実行結果

2026-10-17、Windows、Node.js 24.12.0、Vitest 3.2.7、Vite 7.3.7、Playwrightのインストール済みEdgeで実施。

| 項目 | 実測結果 |
| --- | --- |
| `npm test` | 2ファイル・46件成功（戦闘32件、進行・保存14件）。失敗・スキップなし |
| `npm run build` | 型検査・本番ビルド成功。46モジュール。JS 267.51 kB（gzip 84.63 kB）、CSS 28.28 kB（gzip 7.51 kB） |
| `npm run test:browser` | 正式仕様の全5戦、最終報酬、敗北と再挑戦を実UI操作で成功。勝利状態の注入なし |
| 画面幅 | 320、390、768、1440pxで横方向のはみ出しなし |
| 操作・再開 | 配置・控え・交換・王必須、危険表示、一時停止・1半手進行・速度変更、再読込後の状態とログの完全一致を確認 |
| 成長 | 毎報酬で所持駒が1増える。第2戦後の遺物、第3戦後以降の異能、最終7枚・出陣6枚以内を確認 |
| 配信 | 本番 `dist/` を `/shogi-survivor/` 以下で配信し、React・CSS・アイコンの読込、初戦勝利まで確認 |
| エラー | 最終ブラウザ検証でJavaScript実行時エラー・コンソールエラーなし |

全5戦の通し操作は、毎戦「配置をおまかせ」、報酬は毎回「飛車」。勝利までの半手数は **9 / 53 / 9 / 5 / 9**。第5戦勝利直後は報酬画面であり、最後の駒を選んだ後にクリア画面となることも検証した。別編成での王捕獲・80半手・連続パスの境界は単体テストで確認。

```powershell

$env:TEST_URL = 'http://127.0.0.1:5278/'

```

画面証跡は `artifacts/formal-*.png`。生成物のためGit管理対象外。

## 検証途中の失敗と対処

- このWindowsサンドボックス内では、Vite/Vitestの設定読込でesbuildが `Access is denied` となった。通常権限で再実行し、最終46件とビルドが成功。
- 既存の `dist/` を更新するビルドが、変換後に終了コード1で止まる事象があった。`--emptyOutDir false` で生成できることを確認後、削除先の絶対パスが作業フォルダ内の `dist/` であることを確認し、この生成物だけを削除。標準の `npm run build` を改めて実行して成功した。GitHub Actionsはクリーンなチェックアウトからビルドする構成。
- Word文書を受け取る前の仮実装と古いテストへの参照は正式仕様へ置き換え、改めて全件を検証した。
