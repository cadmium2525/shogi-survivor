# 将棋サバイバー

王と歩から軍勢を育てる、スマートフォン向けの将棋ローグライク・オートバトラーです。**5×5盤・全5戦**。敵の配置を見て布陣を決め、完全自動の戦闘を見守ります。通常の捕獲は一撃撃破で、敵王を取れば勝利です。

提供されたWord文書「ゲーム企画書」「Codex実装指示書」に基づいて実装しています。仕様と構成は [実装計画](docs/IMPLEMENTATION_PLAN.md)、[仕様とテストの対応表](docs/SPEC_COMPLIANCE.md)、検証範囲・結果は [検証記録](docs/TESTING.md) を参照してください。

**プレイURL： https://cadmium2525.github.io/shogi-survivor/**

スマートフォンのブラウザからそのまま遊べます。インストールやアカウント登録は不要です。

## 起動・テスト・ビルド

Node.js **24以上**と npm を推奨します。

```sh
npm install
npm run dev
```

表示されたURL（通常 `http://localhost:5173`）を開きます。同じWi-Fiのスマートフォンでは、ターミナルに表示される Network URL を開けます。OSのファイアウォールで接続が遮断される場合があります。

```sh
npm test
npm run build
npm run preview
```

`npm test` は Vitest の単体テストです。`npm run build` は型検査と `dist/` の生成、`npm run preview` は本番ビルドのローカル確認（通常 `http://localhost:4173`）です。ロックファイル通りに再現する場合は、`npm install` の代わりに `npm ci` を使います。

ブラウザの通しテストは、ビルド後、開発サーバーを起動したまま別ターミナルで実行します。

```sh
npx playwright install chromium webkit
npm run test:browser
```

接続先は環境変数 `TEST_URL`（既定 `http://127.0.0.1:5173/`）で変更できます。インストール済みのEdgeを使うWindows環境は、PowerShellで `$env:PLAYWRIGHT_CHANNEL='msedge'` を設定するとChromiumの追加取得は不要です。Safari系の検証には `$env:PLAYWRIGHT_BROWSER='webkit'` を設定して同じコマンドを実行します。

ブラウザテストは、スマホ幅と縦横切替時の盤面25マス・駒・文字の実寸と配置を検証します。全5戦のクリア・最終報酬・敗北と再挑戦・途中再開・本番サブパス配信も確認し、`artifacts/` にブラウザ別の画面を保存します。GitHub ActionsでもChromiumとWebKitの両方を通ってから公開します。

## 遊び方

1. 王1枚・歩1枚で遠征を始めます。
2. 駒を選び、**下2段**をタップして配置・交換します。王を含め最大6枚が出陣し、残りは控えにできます。敵配置と危険マスを確認して戦闘を始めます。
3. 通常は味方1枚→敵1枚の交互行動です。AIが毎回、陣営内の全駒・全合法手から1手を選びます。同じ初期状態では、同じ行動と結果を再現できます。
4. 勝利後、歩・金・飛の**3候補から駒を必ず1枚**獲得します。第2戦勝利で遺物「オセロの法則」も獲得し、第3戦勝利以降は能力付きの駒が候補に登場します。
5. 第5戦のボスに勝利し、最後の駒報酬を選ぶと踏破です。味方王の捕獲、80半手の上限、双方の連続パスで遠征終了となります。

戦闘は一時停止・1手送り・速度変更で確認できます。ログには移動、捕獲、特殊効果とAIの判断理由が表示されます。

| 特殊能力・遺物 | 効果 |
| --- | --- |
| 鉄壁 | 最初の捕獲を1回防ぎます。攻撃側は移動元に留まり、盾を消費します。 |
| 連撃 | 捕獲に成功すると同じ陣営に追加の1行動。追加行動から連撃は再発動しません。 |
| 分裂 | 捕獲に成功すると、移動元に味方の歩1枚を召喚します。盤上の同陣営は最大8枚です。 |
| オセロの法則 | 行動した陣営について盤面全体を検査し、味方同士が8方向に挟んだ敵を反転します。両陣営に適用し、敵王を挟む方向は反転せず、連鎖再検査も行いません。盤上8枚の上限は上→下・左→右の順で適用します。 |

**将棋の移動を基にした「王の捕獲」が勝敗条件の独自ルール**です。王手・詰み・成り・持ち駒・二歩・打ち歩詰めは採用していません。使用する駒は王・歩・金・飛です。

## GitHub Pagesで無料公開

サーバー・データベース・有料API・外部画像やフォントを使わない静的サイトです。GitHub Free の公開リポジトリと標準の GitHub-hosted runner を利用します。GitHub Pages は公開リポジトリで無料提供され、標準runnerの公開リポジトリでの実行も無料です。[Pagesの提供条件](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[Actionsの料金条件](https://docs.github.com/en/billing/concepts/product-billing/github-actions)

1. この一式を GitHub の**公開リポジトリ**へ配置します。`package-lock.json` と `.github/workflows/deploy.yml` も含めてください。
2. **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. `main` または `master` に push すると、[ワークフロー](.github/workflows/deploy.yml)が `npm ci` → テスト → ビルド → Pages公開を実行します。Actions画面から手動実行もできます。プルリクエストでは検証のみ実行します。
4. Actions の `deploy` に表示されるURLをスマートフォンで開きます。通常は `https://ユーザー名.github.io/リポジトリ名/` です。

Vite の `base: './'` による相対アセット参照で、リポジトリ名のサブパスにも対応します。画面遷移はブラウザ内で完結します。[Vite公式公開ガイド](https://vite.dev/guide/static-deploy.html)

本リポジトリの公開先は `https://cadmium2525.github.io/shogi-survivor/` です。`main` の更新は、テストとビルドが成功した場合にGitHub Actionsから自動公開されます。公開状態はリポジトリのActions画面で確認できます。

## 実装構成

TypeScript + React + Vite、テストは Vitest を使用します。ゲームロジックは `src/game/` の純粋関数へ分離し、React が配置操作・戦闘再生・報酬・画面遷移を担当します。各モジュールの対応は [実装計画](docs/IMPLEMENTATION_PLAN.md) に記載しています。

## 仕様上の最小限の仮定

- 敵の座標・報酬テーブル・AIの評価重みは、企画書の条件を満たす固定データとして定義します。ランダム抽選やシード入力はありません。
- 所持駒の捕獲による永久離脱は採用せず、次戦では所持駒から再編成します。召喚・反転で増えた駒はその戦闘だけに残り、勝利報酬で選んだ1枚が所持一覧に加わります。
- 鉄壁の消費は戦闘ごとに初期化します。分裂による歩は特殊能力を持ちません。
- 最終戦も駒報酬を選択してからクリア画面へ進みます。
- オセロ反転では味方王を端点にできます。敵王が連続列の途中にある方向は不成立とします。鉄壁で移動しなかった行動でも反転を検査し、パスでは検査しません。

## MVPへの追加機能

スマートフォンでの続行を助けるため、進行を同じブラウザ内へ自動保存します。戦闘中の再読込は一時停止状態で再開します。これは企画書のMVP対象外であるセーブの最小限の追加です。アカウント・メタ成長・端末間同期はありません。ブラウザデータの削除で保存は消え、保存機能を利用できない環境でも、そのタブ内で遊べます。

## 既知の制限

- メタ成長・通貨・ショップ・能力の付け替え・合成・レアリティ抽選・オンライン対戦はMVP対象外です。
- 一手先を評価するAIです。長期的な必勝手の探索や全編成の攻略可能性は保証していません。
- 80半手または双方連続パスは、引き分け画面ではなく敗北として扱います。
- GitHub Pagesの公開URLで、スマートフォン相当の画面幅と全5戦の通し操作を検証済みです。スマートフォン実機での確認は未実施です。詳細は [検証記録](docs/TESTING.md) を参照してください。

## 確認済みのクリア例

攻略に迷った場合は、毎戦「配置をおまかせ」を押し、報酬で毎回「飛車」を選ぶと、現在の固定データでは全5戦を突破できます。配置と異能の組み合わせを変えれば結果も変わります。
